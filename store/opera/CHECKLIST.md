# Чек-лист публикации в Opera Add-ons

Расширение: **Прямые брони 0.2.0**  
Пакет: `hotel-direct-0.2.0.zip` — [скачать из Releases](https://github.com/antonbru/hotel-direct/releases/latest) или собрать `npm run build` (в git не хранится)  
Гайд Opera: <https://help.opera.com/en/extensions/publishing-guidelines/>  
Критерии приёмки: <https://help.opera.com/en/extensions/acceptance-criteria/>

## 0. Почему первая загрузка не прошла

Opera-линтер проверяет не только `name`, но и `short_name`: у `short_name` лимит
**12 символов**. В версии 0.1.2 оба поля были «Отель напрямую» (14 символов),
поэтому пакет отклонялся с сообщением `'Отель напрямую' is too long`.

В 0.2.0:

- `name` — **Прямые брони** (12 символов, показывается в каталоге и менеджере);
- `short_name` — **Прямые** (6 символов, техническое короткое имя).

Этого достаточно, чтобы линтер пропустил манифест. Лимит добавлен в
`scripts/validate-manifest.mjs`, чтобы не повторить ошибку.

## 2. Перед загрузкой

- [ ] Войти в аккаунт Opera на <https://addons.opera.com/> (тот же аккаунт, что в браузере).
- [ ] Открыть <https://addons.opera.com/developer/upload/> (или **Develop → Upload**).
- [ ] Проверить пакет:

```bash
unzip -l store/opera/hotel-direct-0.2.0.zip
shasum -a 256 store/opera/hotel-direct-0.2.0.zip
```

Ожидаемо: `manifest.json` в корне, нет `.DS_Store`, `node_modules`, `dist`,
`__MACOSX`; сумма совпадает с указанной выше.

- [ ] Проверить ссылки:
  - поддержка: <https://github.com/antonbru/hotel-direct>
  - политика: <https://github.com/antonbru/hotel-direct/raw/main/docs/PRIVACY.md>
- [ ] Открыть `store/opera/LISTING.md` и держать под рукой для копирования.

## 3. Мастер загрузки

Страницы мастера идут по порядку; названия полей в дашборде могут немного
отличаться, но набор тот же. В актуальном дашборде это может быть не мастер,
а страница версии с вкладками **Details / Translations / Screenshots** —
ориентируйтесь на поля, а не на номера экранов.

### Страница 1 — пакет

- [ ] Загрузить `hotel-direct-0.2.0.zip`.
- [ ] Дождаться проверки: Opera читает `manifest.json`, версию и разрешения.
- [ ] Убедиться, что версия определилась как `0.2.0`, а название — «Прямые брони».

Если загрузка падает на середине: это известная проблема больших файлов;
наш пакет 25 КБ, но помогает смена браузера/сети и повтор с того же аккаунта.

### Страница 2 — название, версия, категория, лицензия

| Поле | Значение |
|---|---|
| Extension name | `Прямые брони` |
| short_name (в манифесте) | `Прямые` — не удлиняйте, у Opera лимит 12 символов |
| Version | `0.2.0` (из пакета) |
| Category | `Productivity` (Travel в текущей форме нет) |
| Support webpage | `https://github.com/antonbru/hotel-direct` |
| License | `Opera Hosting License` |

Про категорию: в актуальной форме Opera нет `Travel`. Выбирайте
**Productivity** — ближайшая категория для утилиты, которая добавляет
информацию на страницы. `Shopping` — запасной вариант, но расширение не
сравнивает цены и не продаёт туры.

Про лицензию: код проекта остаётся под MIT, а hosting license — это право Opera
распространять пакет в каталоге бесплатно и чинить его при необходимости.
Исключительные права вы не передаёте. Если в форме есть только «Apache 2.0» и
«Opera Hosting License», выбирайте hosting license; Apache 2.0 противоречил бы
`LICENSE` в репозитории.

## 5. Критерии приёмки: что и где закрыто

| Критерий Opera | Как выполнено |
|---|---|
| Одна понятная цель | Показать официальный сайт и телефон отеля на странице агрегатора |
| Название не выдаёт связь с другой компанией | «Прямые брони», без брендов агрегаторов и Opera |
| Summary отвечает «что делает» | Одно предложение в `LISTING.md` |
| Description отвечает «как пользоваться» и «как выглядит» | Разделы «Как пользоваться» и «Как это выглядит» |
| Расширение делает то, что описано | Проверено в Opera 139 на Островке и 101hotels |
| Фоновые действия описаны | В описании: чтение ссылки на реестр и запрос к `tourism.fsa.gov.ru` |
| Support-страница относится к расширению | GitHub-репозиторий с инструкцией и issue |
| Иконки в одном стиле | 16/32/48/128 из одного исходника, PNG |
| Иконка — не просто слово на фоне | Белый ключ на тёмно-зелёном скруглённом квадрате |
| Скриншоты качественные, 612×408, белый фон | Три PNG, RGB, non-interlaced, 612×408 |
| Нет незаконного использования чужого контента | Данные — открытый реестр; товарные знаки только в описании, без логотипов |
| Нет брендинга Opera | В названии, иконке и описании нет Opera |
| Нет внешнего JavaScript | Весь JS в пакете; внешний запрос только JSON к реестру |
| Нет азартных игр | Не относится |
| Не «кнопка со ссылкой» | Карточка строится по данным реестра, а не ведёт на один сайт |
| Код можно проверить | Репозиторий MIT, код не минифицирован, сборки нет |
| Нет неиспользуемых файлов | Все 15 файлов пакета подключены манифестом или импортом |
| Нет лишних разрешений | `storage` + `https://tourism.fsa.gov.ru/*` |
| Нет рекламы в content script | Рекламы нет |
| Не меняет referral-параметры | Ссылки и кнопки агрегатора не трогаются |
| Не собирает личные данные | Нет телеметрии, cookies, истории; кэш только локально |

## 6. Риски и заготовки ответов модератору

### Скриншоты — композиция, а не живое окно Opera

Контент снят с реальной страницы с загруженным расширением, но рамка браузера
нарисована нейтрально (без логотипа Opera), потому что в момент подготовки Opera
не была установлена в системе. Если модератор попросит скриншоты именно из Opera:

1. `opera:extensions` → включить **Developer mode** → **Load unpacked** → папка
   `extension/`.
2. Открыть страницу отеля, закрыть модалку дат и cookie-баннер агрегатора.
3. Сделать снимок окна (`Cmd+Shift+4`, затем пробел) на белом фоне.
4. Обрезать/уменьшить до 612×408 без интерлейса, заменить файлы в
   `store/opera/screenshots/`.

### Скриншот с Яндекса (04-yandex.png)

Живая карточка Яндекса отдаёт SmartCaptcha автоматизации, поэтому исходник снят
с сохранённой копии страницы, открытой в Chromium через локальное HTTPS-зеркало
с этим же расширением. В кадре — настоящая разметка Яндекса, не макет.

1. Сохранить HTML карточки (например, из Wayback Machine:
   `web.archive.org/web/<timestamp>id_/<url>`), распаковать, если пришёл gzip.
2. Поднять локальное HTTPS-зеркало с сертификатом на `travel.yandex.ru`.
3. Запустить Chromium с флагами
   `--ignore-certificate-errors --no-proxy-server --host-resolver-rules="MAP travel.yandex.ru 127.0.0.1:8443"`,
   загрузить расширение через CDP (`Extensions.loadUnpacked`).
4. Открыть `https://travel.yandex.ru/hotels/moscow/the-carlton-moscow/`, дождаться
   карточки в левом нижнем углу, снять кадр 1440×900 в `.tmp/store/yandex-page.png`.
5. `npm run store:shots` → `store/opera/screenshots/04-yandex.png`.

`--no-proxy-server` обязателен: при системном прокси Chrome обходит
`host-resolver-rules` и уходит на живой Яндекс, где встречает капчу.

Если модератор попросит живой снимок именно из Opera — открыть страницу отеля
на Яндексе вручную, расширение уже установлено, снять экран (человеку капча
не мешает).

### Content script на страницах агрегаторов

Модератор может спросить, не вмешивается ли расширение в чужой сайт. Ответ:
расширение только добавляет отдельную карточку в Shadow DOM; не меняет цены,
кнопки, ссылки и referral-параметры, не перехватывает клики, не скрывает
элементы агрегатора. Это же записано в `CONTRIBUTING.md` и описании.
В критериях Opera есть прямой пример допустимого сценария: «показать, что товар
можно купить дешевле в другом месте». Карточка — тот же класс альтернативы,
без подмены кнопок и ссылок агрегатора.

### Значок на панели открывает настройки

Основная функция — автоматическая карточка, поэтому клик по значку ведёт в
настройки. Это не «кнопка со ссылкой на сайт»: настройки управляют самой
функцией (выключить карточку, сбросить скрытые). Если модератор сочтёт это
нарушением, можно убрать `action` из манифеста; но тогда пропадёт быстрый доступ
к настройкам.

### Только macOS

Windows и Linux не проверялись локально. В коде нет платформенных API, только
`chrome.storage`, `chrome.runtime`, `fetch` и content scripts. Если попросят —
честно сказать, что тестировали macOS + Opera 139, а остальные платформы
оставлены на ревью.

### Версия 0.2.0

Opera принимает версии из одного–четырёх чисел, `0.2.0` валидна. Если не хотите
публиковать «бету», поднимите версию до `1.0.0` **до** загрузки:

```bash
# extension/manifest.json и package.json
npm run check
npm run build
cp dist/hotel-direct-1.0.0.zip store/opera/
```

Тексты менять не нужно. Скриншот `03-options.png` показывает версию `0.2.0` —
после смены версии переснимите его (`npm run store:capture && npm run store:shots`)
или оставьте версию `0.2.0`.

## 7. Обновления после публикации

1. Поднять версию в `extension/manifest.json` и `package.json` (одинаково).
2. `npm run check`.
3. Закоммитить, поставить тег и запушить его:

```bash
git tag v0.2.1
git push origin v0.2.1
```

4. Workflow **Release** сам прогонит тесты, соберёт zip и приложит его к
   GitHub Release вместе с `SHA256SUMS.txt`.
5. В дашборде у пакета нажать **Upgrade** / **Upload new version** и загрузить
   zip из свежего релиза.
6. Заполнить changelog: что изменилось, без маркетингового шума.
7. Отправить на модерацию. Обновления обычно проходят быстрее первых публикаций.
