# Как участвовать в разработке

Проект бесплатный и открытый: им пользуются гости, а не рекламодатели. Поэтому
ценность — в честных данных и в том, что расширение не мешает сайтам.

Спасибо, что хотите помочь. Ниже — как это сделать без лишних кругов.

## Кому и чем можно помочь

| Роль | Что делать |
|---|---|
| Гость | Сообщить о карточке, где расширение ошиблось или промолчало |
| Разработчик | Взять `good first issue`, починить баг, добавить агрегатор |
| Исследователь | Проверить разметку нового агрегатора, собрать статистику покрытия |
| Дизайнер | Улучшить карточку, иконки, промо-материалы |
| Юрист | Разобрать ToS агрегаторов и требования Chrome Web Store |

Не нужно быть «в команде»: достаточно issue или PR.

## Принципы, которые не обсуждаются

Это не бюрократия — на этих принципах держится доверие к расширению:

1. **Никакой коммерции внутри расширения**: ни партнёрских ссылок, ни комиссии с брони,
   ни платных «подтверждённых» отелей.
2. **Никакой телеметрии и сбора данных**: наружу уходит только запрос к реестру.
3. **Никакого вмешательства в сайт**: не подменяем цены, не перехватываем клики,
   не переходим автоматически, не прячем кнопки агрегатора.
4. **Никаких лишних разрешений**: `storage` + доступ к `tourism.fsa.gov.ru` — всё.
5. **Честность в текстах**: не обещаем «дешевле на 30 %», если не проверяли.

PR, нарушающий эти пункты, будет закрыт — даже хороший по коду.

## Сообщить о баге

1. Проверьте, нет ли уже похожего issue.
2. Откройте **Issues → 🐞 Баг**.
3. Приложите: ссылку на карточку отеля, браузер и версию, версию расширения,
   ошибки из `chrome://extensions` → «Ошибки», скриншот.

Без ссылки на карточку починить почти невозможно: разметка у отелей разная,
а часть карточек не отдаёт реестровый номер вообще.

## Предложить идею

**Issues → 💡 Идея**. Опишите задачу, а не только решение: «на Яндексе не работает»
полезнее, чем «добавьте селектор `.foo`».

Крупные изменения (новый агрегатор, смена источника данных, новые разрешения)
сначала обсуждаем в issue — чтобы не переписывать PR.

## Взять задачу

1. Смотрите issues с метками [`good first issue`](https://github.com/antonbru/hotel-direct/labels/good%20first%20issue)
   и [`help wanted`](https://github.com/antonbru/hotel-direct/labels/help%20wanted).
2. Напишите в issue «беру» — чтобы двое не делали одно и то же.
3. Форкните репозиторий, работайте в ветке `fix/...` или `feat/...`.
4. Откройте PR, в описании — `Закрывает #12`.

Если застряли — пишите в issue, а не пропадайте: задачу можно передать.

## Локальная среда

Нужен только Node.js 20+ (внешних зависимостей у расширения нет).
Python 3 с Pillow — только для перегенерации иконок, не обязательно.

```bash
git clone https://github.com/antonbru/hotel-direct.git
cd hotel-direct
npm run check   # синтаксис + манифест + 27 тестов
npm run build   # dist/hotel-direct-<версия>.zip
```

Загрузить в браузер: `chrome://extensions` → «Режим разработчика» →
«Загрузить распакованное» → папка `extension/`.

Проверка на живой странице (нужен установленный Chrome):

```bash
npm run live -- "https://ostrovok.ru/hotel/russia/tver/mid11253536/orsha_river_club_hotel/"
```

Скрипт сам поднимает headless Chrome, ставит расширение через CDP, открывает страницу,
проверяет, что карточка отрисовалась, и кладёт скриншот в `.tmp/live.png`.

## Правила кода

- `extension/` — без сборщика и без npm-зависимостей. Классические скрипты,
  MV3, минимум разрешений.
- Сеть — только из service worker (`background.js`). Content script не ходит
  в интернет: у реестра нет CORS-заголовков.
- Новый домен или разрешение — только после обсуждения в issue.
- Комментарии — по-русски, по делу. Без «TODO на будущее» без issue.
- Тесты — `node:test`, без библиотек. Новый кейс = новый тест в `tests/`.

## Pull request

1. Один PR — одна задача. Рефакторинг «заодно» — отдельно.
2. `npm run check` должен быть зелёным; CI повторит это на GitHub.
3. В описании: что меняет, как проверить, что не проверено.
4. Скриншот/гифка, если поменялся интерфейс.
5. Ревью — в комментариях PR. Правки лучше отдельными коммитами, сквош сделаем при мерже.

Отправляя PR, вы соглашаетесь, что вклад распространяется под лицензией [MIT](LICENSE).

## Релизы

Версия живёт в двух местах: `extension/manifest.json` и `package.json` — они должны совпадать.
Релиз: тег `vX.Y.Z` → CI собирает zip → GitHub Release с zip-артефактом.
Правила версий: `0.x` — до публикации в Chrome Web Store, дальше semver.
