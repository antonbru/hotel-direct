# Исследование: можно ли показывать прямой сайт отеля на агрегаторе

Проверки выполнены 26–27 ноября 2026.

## Вывод

Да, и без парсинга агрегаторов. Агрегаторы сами публикуют ссылку на карточку отеля
в Едином реестре объектов классификации, а у реестра открытый API с сайтом и телефоном.
Сопоставление получается точным — по UUID записи, а не по названию.

## Что проверено

| Проверка | Результат |
|---|---|
| API реестра без ключа | `GET tourism.fsa.gov.ru/api/v1/resorts/hotels/{uuid}/main` → `websiteAddress`, `phone`, `email`, `coordinates`, `status` |
| Объём реестра | 51 713 записей, 41 453 действующих |
| Сайт в реестре | 56 % действующих (выборка 120), Москва — 59 % (250). Телефон — 78 % |
| Мусор в `websiteAddress` | ~10 %: `vk.com`, автосайты `*.clients.site`, ссылки на агрегаторы |
| Реестровый номер на Островке | блок «Аккредитация», 8 из 8 проверенных московских карточек |
| Островок без блока | на Orsha River Club блок не рендерится, ссылка лежит в `__NEXT_DATA__ → facts.register.link` |
| Реестровый номер на 101hotels | есть, `button[data-href]`, плюс микроразметка адреса и координат |
| Яндекс Путешествия | номер и UUID есть: подпись «Объект №С…» в DOM + `fsaInfo` в `__PRELOADED_REDUX_STATE__` (проверено на 5 карточках) |
| Выгрузка индекса | 52 запроса по 1000 записей ≈ 1 минута |
| Аналоги | Directo, BookBetterDirect (Booking/Expedia/Airbnb); под Островок/Яндекс Путешествия не найдено |

## Яндекс Путешествия: разметка (спайк 27.11.2026)

Капча настоящая: без браузерной сессии страница отдаёт SmartCaptcha («Вы не робот?»),
поэтому curl и headless-браузер бесполезны. Разбор сделан на сохранённых копиях страниц
(Wayback Machine, снимки 02.12.2025 — 17.11.2026) и сверен по номеру с живым API реестра.

Пример карточки: `https://travel.yandex.ru/hotels/moscow/the-carlton-moscow/`

| Данные | Где лежат | Значение на примере |
|---|---|---|
| Реестровый номер (видимая подпись) | `button span[data-qa="text"]` с текстом «Объект №С…», один раз на страницу, под блоком «Часто задаваемые вопросы» | «Объект №С772024004849» |
| Номер и UUID | инлайн-скрипт `window.__PRELOADED_REDUX_STATE__` → `.hotels.hotelPage.hotelInfo.data.hotel.fsaInfo` | `registryId: С772024004849`, `registryUrl: …/hotels/38b955af-…/about-resort` |
| Название, адрес, координаты | там же, объект `hotel`: `name`, `address`, `coordinates{lat, lon}`, `stars` | «The Carlton Moscow», «Москва, Тверская улица, 3», 55.757436 / 37.613116 |
| Похожие отели | `.hotels.hotelPage.hotelInfo.data.similarHotelsInfo.hotels[]` — у них свои `fsaInfo`, брать нельзя | 5 чужих UUID на той же странице |

**Ключевой вывод:** ссылки на `tourism.fsa.gov.ru` в разметке Яндекса нет вообще —
ни в `<a href>`, ни в `data-href`. UUID есть только в состоянии страницы, поэтому
расширение читает его оттуда и сверяет `hotelSlug` с путём адреса (иначе легко поймать
соседний отель из блока «похожие»).

Проверено на пяти карточках: Carlton `С772024004849`, Continental `С772024016586`,
Azimut Олимпик `С772024009235`, МИРРОС Кремль `С772024012923`,
Мамэзон Покровка `С772024001451` — во всех случаях номер в DOM совпал с `registryId`
в состоянии, а UUID из `registryUrl` открыл карточку реестра с сайтом и телефоном.

**Если отель не в реестре:** `fsaInfo: null` и подписи «Объект №» на странице нет —
расширение молчит, как на Островке без блока «Аккредитация».

**Ограничение SPA:** при переходе на другую карточку внутри сайта инлайн-скрипт
остаётся от прошлого отеля. Расширение это замечает (slug не совпал с адресом)
и один раз запрашивает ту же страницу, разбирая SSR-состояние уже нужного отеля.

## Почему это стало возможно

С 1 сентября 2025 года агрегаторы обязаны показывать только объекты с действующей
записью в реестре. Поэтому реестровый номер (и ссылка на карточку) есть прямо
на странице отеля — это не догадка, а следствие требования.

## Ограничения

- Сайт есть не у всех отелей: примерно половина карточек покажет только телефон.
- Зарубежные отели в реестр не входят.
- Если на карточке нет ни блока, ни реестрового номера в состоянии страницы,
  расширение молчит: сопоставление по названию без индекса даёт ложные привязки.
- ToS агрегаторов на вмешательство в интерфейс не проверялся юридически.

## Экономика (для контекста)

Комиссия агрегаторов в России — 15–25 % от чека бронирования. Отсюда и мотив отеля
и гостя: прямой канал дешевле. Расширение комиссию не берёт и партнёрских ссылок
в MVP не использует.
